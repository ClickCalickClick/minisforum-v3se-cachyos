 2. Read the commit message once. It is written in your voice; make
    sure you are happy to stand behind it.

OPTION A - git send-email (recommended)
---------------------------------------
 1. Install git if needed:      sudo pacman -S --needed git
 2. One-time identity:
        git config --global user.name  "Your Name"
        git config --global user.email "you@example.com"
 3. One-time SMTP setup for Gmail. Gmail needs an "App password"
    (Google Account -> Security -> 2-Step Verification -> App passwords).
    Create one named "git send-email" and keep it private. Then:
        git config --global sendemail.smtpServer     smtp.gmail.com
        git config --global sendemail.smtpServerPort 587
        git config --global sendemail.smtpEncryption tls
        git config --global sendemail.smtpUser       you@example.com
    (Do NOT store the app password in git config; git will prompt for
     it when sending, or you can use a credential helper.)
 4. Send it (one command, from this folder):

        git send-email \
          --to="Takashi Iwai <tiwai@suse.com>" \
          --to="Jaroslav Kysela <perex@perex.cz>" \
          --cc="linux-sound@vger.kernel.org" \
          --cc="Samuel Dionne-Riel <samuel@dionne-riel.com>" \
          0001-ALSA-hda-realtek-Fix-internal-mic-on-Minisforum-V3-SE.patch

    It shows a preview and asks "Send this email? [y/N]" - answer y.
    Add  --dry-run  to the command to see what it would do first.

OPTION B - dry run / if you want to look before you leap
--------------------------------------------------------
    git send-email --dry-run --to=... (same as above)
    prints the full message without sending anything.
